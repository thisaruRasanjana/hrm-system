# IN2901 University Review: HRM Recruitment Module Study Guide

## 1. Codebase Overview

### What does this module do overall?
This module is a comprehensive Human Resources Recruitment System. It allows HR managers to create job postings (vacancies), provides a public-facing portal for candidates to apply by uploading their CVs, and automatically screens those CVs using Artificial Intelligence to rank candidates. Furthermore, it allows HR to configure interview panels, capture structured interview scores, and track the candidate lifecycle through to a final hiring decision.

### Main Files and Folders (Architecture)
The system is divided into three separate pieces of software that communicate with each other:

1. **`frontend/` (The View/UI):** 
   - Built with Next.js and React.
   - Contains components and pages (e.g., `app/recruitment/page.tsx`) that the HR team and candidates interact with.
   - Responsible for rendering the interface and making HTTP requests to the backend.

2. **`backend/` (The Core API / Controller & Model):**
   - Built with Python and FastAPI.
   - `app/recruitment/models.py`: Defines the database tables (the "Model" in MVC).
   - `app/recruitment/schemas.py`: Defines strict validation rules for data coming in from the frontend.
   - `app/recruitment/service.py`: Contains the "Business Logic". This is where data is saved to or fetched from the database.
   - `app/recruitment/router.py`: Exposes HTTP endpoints (URLs) that the frontend can call (the "Controller" in MVC).

3. **`ai_service/` (The Microservice):**
   - A completely independent FastAPI application running on its own port.
   - Responsible strictly for reading PDF/DOCX files and communicating with Google's Gemini AI to score candidates.
   - **Why separate it?** AI processing is resource-intensive and requires completely different libraries (like PyMuPDF and GenAI) compared to standard CRUD database operations.

### Technologies & Frameworks Used
- **Frontend:** Next.js (React framework for building UIs quickly), Tailwind CSS (for styling without writing massive CSS files).
- **Backend:** FastAPI (Modern, fast Python web framework for APIs), SQLAlchemy (An ORM that lets us write Python code to interact with the database instead of raw SQL).
- **Database:** PostgreSQL (A robust, production-grade relational database).
- **AI:** Google Gemini 2.x API (Used to intelligently parse unstructured CV data).

## 2. Feature-by-Feature Breakdown

1. **Vacancy Management:** HR can create, edit, and delete job postings. Jobs have statuses: "Draft" (hidden), "Active" (public), and "Closed".
2. **Public Job Portal:** Candidates can view "Active" jobs and upload their CVs (PDF/DOCX).
3. **Automated AI CV Screening:** When a CV is uploaded, the system saves the file and triggers a "Background Task". This task sends the CV to the AI Microservice, which reads the text, extracts the candidate's name, email, and phone number, and scores their relevance to the job description out of 100.
4. **Interview Panel Setup:** HR can assign active employees to be the "Panel Head" or "Panel Members" for a specific job, and attach a Zoom/Google Meet link.
5. **Interview Evaluation (Scorecards):** After interviewing a candidate, panel members fill out a scorecard rating the candidate on 5 metrics (Technical Skills, Problem Solving, Communication, Cultural Fit, Attitude) out of 5.
6. **Final Hiring Decision:** The Panel Head can view all scorecards, see an averaged score, and make a final binding decision (e.g., "Proceed to Next Round", "Job Offered", "Rejected").

## 3. Database Breakdown

We used SQLAlchemy to define our PostgreSQL database. Every table and column was carefully typed.

### Table: `vacancies` (Stores Job Postings)
- `id` (Integer, Primary Key)
- `title`, `department` (String, length-constrained for DB efficiency)
- `experience_level` (String)
- `description`, `requirements` (Text - allows unlimited length for rich HTML content)
- `status` (String - "Draft", "Active", "Closed")

### Table: `candidates` (Stores Applicant Details)
- `id` (Integer, Primary Key)
- `full_name`, `email`, `phone` (String)
- `ai_score` (Float - Stores the 0-100 percentage generated by Gemini)
- `cv_file_path` (String - The absolute path on the server where the PDF is stored)

### Table: `applications` (Links a Candidate to a Vacancy)
- `id` (Integer, Primary Key)
- `vacancy_id`, `candidate_id` (Foreign Keys linking to the respective tables)
- `status` (String - Tracks lifecycle: "Uploaded", "First Round", "Job Offered", etc.)

### Table: `interview_panels` (Configures who interviews who)
- `id` (Integer)
- `vacancy_id` (Foreign Key)
- `panel_head_id`, `panel_member_1_id`, `panel_member_2_id` (Foreign Keys linking to the `employees` table)

### Table: `interview_evaluations` (Stores individual scorecards)
- `technical_skills`, `problem_solving`, etc. (**SmallInteger** - Chosen instead of Integer because the score is always 0-5. SmallInteger uses half the database memory).
- `overall_score` (Float - computed mathematically based on the 5 metrics).

### Table: `employees` (Stores internal company staff)
- `email` (String(254) - 254 is the maximum length of an email address according to RFC-5321 standards).
- `gender` (**CHAR(1)** - Chosen instead of VARCHAR because gender codes like 'M', 'F' are exactly 1 character, making CHAR the most optimal database type).

## 4. Function-by-Function Explanation

*(Located in `backend/app/recruitment/service.py`)*

- **`create_vacancy()`**: Takes a validated Pydantic schema, converts it to an SQLAlchemy ORM object, and saves it to the database (`db.commit()`). Wrapped in a `try/except` block to catch database failures.
- **`upload_cvs_to_vacancy()`**: Validates the file extension and size (Max 5MB). Saves the file locally using a unique UUID to prevent file-name collisions. Creates an Application record and queues `process_cv_background()`.
- **`process_cv_background()`**: A background task that runs asynchronously. It calls the `ai_client` (making an HTTP request to our AI Microservice port 8001) to get the AI score. It updates the database behind the scenes so the user doesn't have to wait for the AI to finish loading.
- **`submit_evaluation()`**: Receives 5 scores (0-5). It calculates the `overall_score` mathematically: `(sum_of_scores / 25) * 100`. It ensures a user cannot submit two evaluations for the same round.
- **`save_final_decision()`**: Saves the Panel Head's decision. Depending on the decision (e.g., "Job Offered"), it automatically updates the underlying Application status so the candidate moves to the correct pipeline stage.

## 5. Key Concepts I Need to Understand

### 1. MVC (Model-View-Controller) Architecture
This is a design pattern used to separate code logic. 
- **Model:** How data is structured (SQLAlchemy files).
- **View:** What the user sees (Next.js React components).
- **Controller:** The routing logic handling requests (`router.py`). We went a step further and added a **Service Layer** (`service.py`) so routers only handle HTTP logic, while services handle pure database logic.

### 2. RESTful APIs
REST is a standard for building web APIs using HTTP methods.
- `GET` requests fetch data (e.g., get a list of vacancies).
- `POST` requests create data (e.g., submit an evaluation).
- `PATCH` requests update existing data.
- `DELETE` requests remove data.

### 3. Pydantic Validation (Schemas)
Before data ever touches our database, it passes through `schemas.py`. Pydantic checks if the data is correct. If a user tries to send an `experience_level` of "God-Tier" instead of "Junior" or "Senior", Pydantic automatically rejects it with an HTTP 422 Error.

### 4. Background Tasks
AI takes several seconds to process a PDF. If we made the user wait for the AI to finish while uploading their CV, the website would freeze and feel slow. Background Tasks allow us to return a "Success! Uploaded" message immediately to the user, while the server crunches the AI data quietly in the background.

## 6. Likely Review Questions & Answers

**Q: Why did you separate the AI logic into a different microservice instead of putting it in the main backend?**
A: Modularity and dependency management. AI libraries (like GenAI and PDF extractors) are heavy and can cause version conflicts. Furthermore, AI tasks take a long time to run. By isolating it, if the AI service crashes or slows down under heavy load, the main HRM system (login, employee management, vacancy creation) remains perfectly fast and unaffected.

**Q: How do you handle errors in your database operations?**
A: Every database write operation (like `db.commit()`) is wrapped in a `try/except` block. If the database crashes, we use `db.rollback()` to undo any partial changes, preventing data corruption. We then log the exact error using Python's `logging` module and return a safe `500 Internal Server Error` to the frontend using an `HTTPException`.

**Q: Why do you use `UUID`s for uploaded files instead of the original file name?**
A: If two candidates upload a file named `Resume.pdf`, the second upload would overwrite the first one. By renaming files to a Universally Unique Identifier (UUID) like `123e4567-e89b-12d3...pdf`, we guarantee file names will never clash.

**Q: What is the purpose of `schemas.py` if you already have `models.py`?**
A: `models.py` defines how data is stored in the Postgres tables. `schemas.py` defines how data should look when it is sent by the user over the internet. For example, a user sends a password via a schema, but we only store a hashed password in the model. Schemas protect the database from bad user input.

**Q: How did you ensure your code is reliable?**
A: I implemented a comprehensive unit testing suite using `pytest`. We mock the database session, meaning we can run dozens of tests in milliseconds without needing a real database. We test our math formulas, our input validation boundary cases, and our core business logic.

**Q: What happens if the AI fails or Google's API goes down?**
A: The system degrades gracefully. If the AI service fails, the `process_cv_background` task catches the error. The candidate's application is still saved as "Uploaded", and HR can manually review the CV by clicking "View Details", ensuring the recruitment pipeline isn't completely blocked.
